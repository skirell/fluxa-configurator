# Инструкции для дальнейшей работы

## Порядок начала задачи

1. Прочитай корневой `AGENTS.md` и этот файл полностью.
2. Открой только профильные документы из таблицы в [README.md](README.md).
3. Проверь `git status --short`, чтобы не перезаписать пользовательские изменения.
4. Найди затрагиваемые исходники через `rg`; не полагайся исключительно на память.
5. Для изменения поведения сначала определи источник истины: декларативная карта, модель, менеджер, UI-поле, валидатор или Electron main process.

## Общие правила изменения

- Работай с исходниками в `src/`; `out/` и `dist/` генерируются и игнорируются Git.
- Не переписывай крупные файлы целиком без необходимости. Особенно осторожно меняй `AppController.ts` и `SidebarRenderer.ts`.
- Не встраивай вручную в контроллер список полей, уже описываемый через `ParamOption`.
- Не дублируй один и тот же бизнес-инвариант в нескольких слоях без причины. Укажи, какой слой отвечает за структуру, тип, required-состояние и кросс-полевое правило.
- Сохраняй русскоязычный стиль пользовательских сообщений и существующие JSON-имена с учётом регистра (`OnOff_*`, `PlayPause_state_topic`, `targetTemp_*`).
- Сохраняй текущий стиль: TypeScript/CommonJS, табы, одинарные кавычки, точки с запятой, LF. Формат задают `.prettierrc.json` и `.gitattributes`.
- Не меняй внешний JSON только ради внутренней эстетики: формат должен оставаться совместимым с прошивкой Fluxa.

## Инварианты, которые нельзя потерять

- Страницы и блоки нумеруются с 1; после вставки, удаления, копирования и drag-and-drop номера пересчитываются.
- Максимум 100 страниц и 6 блоков на страницу.
- Base-параметры лежат в `data`, variant-параметры — в `data.variant`, а `variant_type` — в `data`.
- `required: true` требует непустое значение. `optional: true` разрешает отсутствие ключа в JSON. Флаги не взаимозаменяемы.
- Неoptional-поле без значения получает типовой дефолт при сериализации.
- Feature-объекты читаются и создаются в лексикографическом порядке ключей. Для генерации применяй `buildOrderedFeatureKeys()`.
- Загрузка намеренно терпима к восстановимым ошибкам: допустимая часть блока сохраняется, проблема записывается в `loadIssues`.
- Сохранение полного проекта блокируется при errors, но warnings сами по себе его не блокируют.
- При смене variant сначала сохраняются живые базовые значения формы, затем сбрасывается старый variant.
- При добавлении DOM-listener предусмотренный `dispose()` должен удалять глобальные обработчики и очищать вложенные поля.

## Маршрут расширения схемы

При добавлении типа, подтипа или параметра проверь весь маршрут:

1. enum;
2. map типа/подтипа;
3. label/order options;
4. base/variant/feature/lameli/settings ParamOption;
5. constructor map, если добавлен новый `FieldType`;
6. загрузочный type-check и дефолт;
7. required/dependency/cross-field/nested validation;
8. сериализацию base/variant и optional-пустых значений;
9. remote documentation URL и anchor;
10. автоматические тесты и ручной round-trip.

## Проверка завершения

- Код: `npm test` как минимальный gate.
- UI: `npm run convert`, затем `npm start` и профильный smoke-test.
- JSON: load → edit → preview/save → reload с проверкой структуры и значений.
- Packaging: проверять собранный артефакт, а не только запуск из source checkout.
- Документация: обновить этот каталог, если изменились команды, схема, архитектура, ресурсы или известное состояние.
- Перед отчётом: `git diff --check` и `git status --short`.

Если команды недоступны в окружении, явно укажи, что именно не запущено и почему. Не называй непроверенный результат успешным.
